# 当前日报看板模板

本规范用于本项目的日报看板及同日图文分析报告。指标计算以 [metrics.md](metrics.md) 为准；AI 文字分析按 [operational-analysis.md](operational-analysis.md) 执行。周/月报继续使用已有对应构建脚本，不直接套用日报的 Tab 结构。

## 顶部经营摘要

摘要位于 Tab 之外，切换分类时保持展示。保留四组指标：

1. 下单数量，辅助显示订单涉及线路数。
2. 自动报价率及自动报价订单数。
3. 全自动报价率及全自动报价订单数，位于自动报价之后，作为重点关注指标。
4. 成单率及成单数量。

比例展示分子、分母，指标保留计算口径提示。全自动报价不要求已成单，不等于修正后的自动报价成单归因；两者不能互相替代。

## 五个业务 Tab

新日报的趋势范围固定为分析日期及前14个自然日，共15天。生成前必须逐日刷新并校验完整快照；即使已有历史文件也需刷新。经营、自动报价、二次竞价、成单率与价格趋势使用同一日期窗口。零订单日保留日期点，缺失或接口失败不能用0补点，也不能静默跳过后交付。新安装不依赖旧机器的历史目录。日报核心指标分母仍为分析日期当天订单，不汇总15天订单。仅重建样式时读取已有数据，不自动拉数。

| Tab | 展示内容 |
| --- | --- |
| 经营总览（默认） | AI 运营分析、最近15天经营趋势、渠道表现、A/B/S 成单结构、小时分布。 |
| 自动报价 | 未自动报价订单、线路覆盖及维护更新、自动报价与全自动报价构成及趋势、全自动报价省份分布、订单明细下载。 |
| 二次竞价 | 有效二次竞价及标记异常、价格状态构成及趋势、销售/距离/线路推送分布及筛选、二次竞价省份分布、明细下载。 |
| 成单与利润 | 顶部四项成单贡献率、报价路径成单率及趋势、修正后成单归因、确认成本利润、下单到成单漏斗。 |
| 价格与异常 | 全量及成单价格对比、高于/低于明细及筛选、价差趋势、异常 Top10 复核及证据、差价订单省份分布。 |

省份分布随所属业务展示，不再单独堆成一个章节。切换 Tab、展开模块时初始化或调整可见图表；保留可聚焦的 Tab 和键盘切换。

## 成单贡献率位置

「成单与利润」顶部默认直接展示这四项：

- 自动报价方式成单贡献率。
- 人工竞价方式成单贡献率。
- 自动报价方式成单贡献率（修正）。
- 人工竞价方式成单贡献率（修正）。

原口径与修正口径并排对照，分母均为总下单数。下方再展示修正后的自动/人工报价路径成单率，分母为各自路径订单数。两类指标分区并说明分母，避免误读。

## 展开与底部说明

- 所有可折叠模块默认展开，仍允许用户手动收起。
- 删除底部数据指标勾选设置，不保留相关的本地存储隐藏逻辑。
- 「数据口径与时间范围」作为常驻说明区，不使用折叠和大型时间卡片。桌面分列统计口径、记录时间范围，窄屏纵向排列。
- 说明订单范围、快照状态、未自动报价、全自动报价、贡献率与路径成单率的区别。
- 列出下单、自动报价、成单、运力竞价四类记录时间。说明它们属于本批订单的事件时间，后续事件可能跨下单日；分析生成时间不等于数据刷新时间。

## 价格明细筛选和滚动

高于、低于两侧明细分别保留搜索、金额筛选、导出和筛选结果单量：

- 搜索订单或线路；与金额条件同时生效。
- 金额条件明确标为「差价绝对值大于 X 元」，输入非负金额。空值不限，采用严格大于，不包含等于阈值的订单；负差价也按差距大小筛选。
- 使用原始带符号差价计算绝对值，不解析格式化金额、不使用四舍五入后的显示金额筛选。
- 展示「符合筛选 X / 共 Y 单」。无结果时不导出订单；金额无效时提示输入有效的非负金额。
- CSV 只导出当前符合搜索和金额条件的订单，保留原有订单号、线路、两侧干线价、差价字段；不改变总体图表或指标的分母。
- 标题、筛选及导出栏置于表格滚动区之外。只让表格内部滚动，表头固定在同一滚动区顶部，避免嵌套滚动导致表头移出。
- 窄屏两侧明细上下排列；表格有足够最小宽度，并允许表内横向滚动，避免线路文字挤成一字一行。

## AI 运营分析

在经营总览中，摘要之后、趋势之前直接展示保存的分析：一句话总体判断、最多5条有数据依据的结论、最多3条有处理对象和观察指标的行动，以及影响判断的数据限制。

数据计算和校验后，由执行任务的 AI 按提示词生成结果，构建脚本只准备数据包、校验并展示。结论证据值来自事实指标；行动关联具体发现。日期或数据指纹不匹配时停止展示旧分析。缺少有效分析时展示经营事实和待生成状态，不将固定数字复述标成 AI 结论。

完整流程、JSON 结构及归因限制见 [operational-analysis.md](operational-analysis.md)。生成日报时完成该流程后再交付，不能仅运行 CLI 就宣称 AI 分析完成。

## 完整报告与交付检查

- 保留完整报告/分类查看切换及打印入口。完整报告展示所有 Tab 的内容。
- 打印时展开所有分类和模块，解除表格滚动高度限制，展示全部行；结束后恢复原视图、展开状态和过滤行状态。
- 生成文件为 `outputs/MMDD_api_analysis/MMDD_visual_dashboard.html` 与 `MMDD_图文分析报告.html`。沿用项目构建脚本，避免只手改生成 HTML，导致下次生成丢失调整。
- 检查默认总览、四组摘要、贡献率位置、默认展开和常驻说明；确认没有指标勾选设置。
- 验证高/低明细正负差价、恰好等于阈值、空金额、组合搜索、无结果及导出订单一致性。
- 实际滚动两侧表格，确认表头固定且筛选栏不移动；检查桌面、窄屏、手机及打印布局，不只检查 CSS 中存在 `sticky`。
- 确认 AI 结果与当前快照一致、证据引用有效，文字中的数字和原因判断也已人工式复核。运行与改动相应的项目测试。
